# Fresh native smoke recipe

Portable adaptation of the accepted `fresh-smoke-20261018` seed90341 recipe. Historical user acceptance on 2026-10-18: “This looks good. Let's call the reusable smoke recipe complete. What's next?” `lineage.json` identifies the original source hashes. This migration has syntax/path checks only: no new bake, rendered visual approval, cross-device reproducibility, or Unreal runtime validation is claimed.

Execution follow-up, 2026-10-19: the migrated seed90379 preview completed a fresh 65-sample GPU bake on the verified RX 9070 XT and both 16-frame lit/opacity render passes. Explicit platform selection resolved duplicate OpenCL architecture-name entries. This supersedes the migration-only execution limit above for that run; user visual approval, atlas packing, cross-device repeatability and Unreal validation remain separate.

Requires Blender with the existing `bl_ext.user_default.continuum_flow` 0.4.0 extension enabled/available, its OpenCL dependencies, and a working GPU runtime. Nothing installs software or changes user preferences. Other add-on versions are unverified. Supply absolute Blender, Python, config, and new output paths. Output must be outside the plugin source tree and must not already exist. `-Gpu` matches exactly one enumerated OpenCL GPU device name (case insensitive substring); the actual solver device is verified as that GPU, with no CPU fallback.

OpenCL may expose architecture names instead of retail board names and may enumerate the same GPU through multiple platforms. Match the device name reported in the diagnostic inventory and supply `-OpenClPlatformIndex <index>` to disambiguate when needed. The selector preserves the add-on's flattened GPU slot, checks the exported platform/device descriptor and verifies the actual solver device; it never silently chooses the first duplicate. The run receipt records the selected descriptor and available board identification.

Run `reproduce.ps1 -BlenderPath <absolute-blender-executable> -PythonPath <absolute-python-executable> -OutputPath <new-external-directory> -Gpu <device-name-substring> -PreflightOnly` first. This validates configuration and paths without loading Blender or checking hardware availability. Omit `-PreflightOnly` to bake and render lit and opacity passes. Existing destinations, including failed partial runs, are preserved; use another output directory. `-Pack` explicitly opts into root `pack_flipbook.py` packaging (requires its Pillow/NumPy dependencies). Hold this switch when motion approval is required. Without it, the root helper produces GIF/contact previews from the native PNGs with `--preview-only`; no atlas is produced.

After reviewing an existing run, package its exact frames with the root helper: `python pack_flipbook.py --input <existing-run>/render-lit/frames --output <new-packed-lit-directory> --fps 8 --columns 4 --rows 4`. Repeat for `render-opacity/frames` with a distinct new output. This performs no bake or rerender. Do not rerun the simulation merely to add an atlas to an approved motion preview.

The physical recipe is unchanged: 12×10×14 domain, full-domain native GPU smoke advection, 64 solver frames plus cache endpoint, warm pulsed source, buoyancy, vorticity, turbulence and two overlapping same-direction traveling vortices. No fuel, combustion or extra pressure. Small animated shader noise modulates actual advected density; it is not independently simulated turbulence. Fixed orthographic camera, lighting, AgX and Eevee settings retain the accepted recipe.

`variation.json` retains all demonstrated controls: seed90341, .065 cell size, turbulence amplitude30, source width1 and upward speed1. The seed can vary; other exposed values are bounded but their combinations lack visual acceptance. Finer cells can increase memory and bake cost.

Rendering uses source frames17..62 every third 24fps frame: 16×256px frames at8fps, two seconds. Lit extinction is2.3; lighting-free black-RGB opacity pass extinction is.65. Native PNGs are16bit; downstream preview conversion is approximate. Opacity is non-color data. A black-RGB opacity pass is an alpha/data master, not a ready neutral-colored smoke texture. Lit color retains authored lighting. The selected one-shot window ends with smoke remaining: no seamless-loop or complete birth/death claim.

Keep `simulation/cache` beside saved scenes. Cache manifests use paths relative to the simulation run; render scenes and receipts point to that newly created cache, never original experiments. Reproduction remains dependent on the recorded Blender/add-on/driver environment; matching seeds alone does not establish cross-version/device bit identity.
