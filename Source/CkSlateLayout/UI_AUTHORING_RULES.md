# In-game UI authoring rules

Read and apply this guide before creating or changing an in-game UI with CkFoundation.
It owns the reusable visual, composition and verification rules for the CkSlateLayout /
CkYoga pipeline and authored UMG hosts. These rules apply in consuming game projects;
CkTests is not required to understand or apply them.

Use [AUTHORING.md](AUTHORING.md) for supported markup, CSS, controls and native contracts,
and [CkWidgets authoring](../CkWidgets/AUTHORING.md) for the reflected session and UMG
integration. This guide sets the quality bar; it does not add browser features or
override those API contracts. Gym fixtures, screenshots and historical test receipts
belong in CkTests rather than in this canonical guide.

## Standing rules

- **Start from the actual reference.** Break it into typography, spacing, artwork, translucency, fading, borders/outlines, interaction, and animation layers. Save reference dimensions and the widget/state breakdown. A mockup guides composition but does not prove a native result. For replication, compare native captures with the reference at the same resolution and crop; identify specific remaining differences. Do not claim a percentage match without a defined measurement.
- **Choose and prove the fonts before polishing layout.** Declare named Regular/Bold/fallback faces through the shared font registry, use appropriately licensed fonts, and stage their licenses. Set ordinary text families through CSS `font-family`; literal HTML font attributes belong only to custom controls whose grammar supports them. Select the family on every relevant node or shared class: CSS has no inheritance, and custom controls have their own font properties. Do not silently substitute the default face or assume that loading a file proves it is used. Inspect rendered headings, body text, numbers, and key legends for their actual face and glyph coverage. Keep ornamental headings separate from readable body copy. Font sizes are Slate points even when written with `px`; measure the face's natural line box at the final scale instead of setting height equal to font size. Exercise long labels and localized glyphs before fixing bounds. Include dynamic and disabled button labels: measure the unwrapped label against the native inner content width after padding, not the outer button width. Exercise the empty state even when there is no selected item.
- **Center the label and its container deliberately.** `horizontal-align`/`vertical-align` place layout children; `text-align` justifies text inside its own bounds. Neither substitutes for the other. Use native text measurement and inspect the painted baseline, padding, and visual centering. Use supported outline/shadow treatment where the reference needs contrast, not larger text. Match background alpha and edge fades over both light and dark scenery; an opaque rectangle is not an acceptable stand-in for a translucent panel.
- **Treat spacing, text roles and material layers as a contract.** Define a small shared spacing scale and semantic ink colors before authoring. Pass CSS variables through the authored session config's StyleTokens map; the accepted map is frozen for that session and retained across reloads. Apply insets on the content owner inside its decorative frame, leaving the frame itself full size. Separate character name, level label, level value and class when their faces, colors or emphasis differ. Use distinct heading, body, secondary, muted, gain and loss roles; justify labels left and numeric comparison columns right. Use dedicated symbolic stat glyphs, not unrelated item thumbnails. Reuse the same inspection-card anatomy on both sides, with explicit positive, negative and neutral deltas. Measure rendered text unions against frame insets at every target size, including long names and multi-line descriptions; passing outer-box containment alone does not prove padding. Supply details must collapse gear-only sections as a unit.
- **Reuse structure and behavior from the first instance.** Use the shared `key-hint` for keycaps, including actionable E/Close and passive labels; change it once instead of offsetting each label. Use document-local typed templates for repeated spell/item/equipment slots, and registered native controls for reusable interaction or rendering. Shared widgets are supported. Cross-file template libraries remain unsupported, so reuse a native control or deliberately maintained source definition when composition spans documents. Give variants parameters/styles rather than copied markup.
- **Let each frame own its contents.** Nest the icon, overlay, quantity/timer, and inset inside the slot's layout box with explicit padding; arrange slots in a row/grid. Do not place six icons independently over six apertures baked into one background image. Large ornamental artwork decorates the composition; it must not define invisible content bounds. Verify wide and narrow icons, long quantities, empty/disabled slots, and selected/focused borders inside those bounds.
- **Model the visual effect, not a superficial substitute.** A cooldown wipe is a filled clockwise mask over the icon with a timer while recharging, not a thin progress ring. A liquid orb separates fill level, moving texture UVs, fixed spherical shading/glass highlights, and an outer frame. Do not animate the highlight with the liquid or flatten live controls into a screenshot. Use existing `hud-ability` and `hud-orb` capabilities before adding another implementation; extend the shared pipeline when an effect is genuinely missing.
- **Keep state typed and updates coherent.** Stable record keys, selection, equipment assignments, eligibility, and quantities belong to the model. Validate all required inputs before publishing; malformed changes and rejected reloads preserve the accepted state. Multi-step operations must publish coherently or retire/roll back the whole operation. The reflected session currently publishes individual scalar values, so do not claim a batch scalar transaction. Exercise stale IDs, invalid drops/actions, removal/reordering, release, and retained references as applicable.
- **Allow for fractional scaling and resolve collection focus by identity.** Do not make a wrapping row consume every available pixel: leave room for DPI rounding and assert the intended column count plus containment at each tested size. Alignment belongs on the child slot; setting alignment on a row does not center all of its children. Prefer natural text height with explicit child alignment when mixing labels and key hints. Resolve repeated controls through their stable record key and local control ID, refresh a changed presenter before focusing it, and reacquire controls after record replacement.
- **Keep reference anchors stable when text varies.** A shorter hint or label must not make a flex spacer redistribute the freed height and move adjacent controls away from their measured reference positions. Reserve the intended hint line box or anchor the neighboring region explicitly, then inspect both short and long text states at the reference size.
- **Keep authored ownership and pointer reachability explicit.** A popup must retain its authored slot while closed and transfer it to the popup without duplicate parents. Decorative images and their structural sizing wrappers must let pointer input reach controls below them. Test a routed click through the final composed screen; directly invoking a control callback cannot establish hit-test reachability.
- **Audit visual and behavioral completeness separately.** Before calling a screen complete, compare it against the reference by region and record missing detail. Active filter styling must represent filter state independently of focus. Key hints must name the action that actually runs for the current selection, and unavailable actions must not present an active target. Hide or reveal the whole comparison component, including tooltip content, rather than only its body text. Derived character totals and signed comparison deltas must come from typed item stats; rarity is not a numeric upgrade test. Inventory capacity counts owned slots independently of filtering. Explicitly expose ambiguous destinations such as two ring slots.
- **Build detail from independent reusable assets.** Use separate environmental art, slot backplates, item icons, character imagery and typography; keep the live slot responsible for its bounds. Use shared inspection-card and slot templates for repeated anatomy. Measured tooltips should grow with their content, not retain a tall fixed blank slab. Verify all custom controls are registered in the actual reflected session, even when a native example already supports them. Test the full pointer drag path and render a readable drag thumbnail/name, rather than treating a proposal callback as drag-and-drop proof.
- **Verify pixels and interaction through the production path.** Source preflight and geometry tests cannot prove that Slate drew the intended result: the cooldown mesh once passed geometry checks while drawing no shade. Add a focused real-renderer assertion for the effect, inspect captures, and compare animation frames while checking that static lighting remains fixed. Test actual screen activation through the consuming project's host, input ownership, reload, and teardown. Report exactly which checks passed and any other failures; a focused green gate is not a repository-wide result.

Treat safe zones, non-16:9 aspect ratios, readable UI scaling, physical gamepad navigation, live gameplay adapters, and cooked resource/font lookup as separate acceptance requirements. Editor captures and a fixed reference canvas scaled to fit do not prove them. Record which requirements the consuming project has actually verified.

## Authoring sequence

1. Read the reference and identify typography, geometry, artwork, state and behavior separately. Save reference dimensions and any generated-art prompts. Treat generated labels, counts and geometry as illustrative until deliberately specified.
2. Record each widget's ID, parent, template/repeat/slot scope, native role, dimensions, bindings, actions and states. Define shared spacing, semantic colors, font roles and frame-safe insets before filling the layout.
3. Define typed model state independently of the artwork. Validate complete inputs before publishing; rejected actions or source reloads must preserve accepted state or explicitly retire the whole operation.
4. Author structure and bindings in markup and supported style properties in CSS. The native mount owns each region root's size; put explicit sizing, growth and alignment on a child. Use explicit font families and measured line heights.
5. Compose shared controls and typed templates first. Add a reusable native registered control only when interaction, measurement or rendering needs a missing capability. Verify registration through the actual host, including the reflected session for scripted UMG.
6. Run source/contract checks available in the consuming project to catch scoped-ID, template, class and binding mistakes. These checks supplement native admission and runtime validation; they do not prove rendering.
7. Exercise the production screen through its real host: input/focus ownership, routed clicks and drag/drop where applicable, model mutation, invalid requests, reload and teardown. Respect deferred control and presenter updates. Use the project's supported build/test runner; CK projects use UnrealToolbox.
8. Inspect native captures at the reference resolution and the project's smallest/largest supported sizes. Exercise long text, empty/disabled/selected states, edge tooltips, animation and the relevant aspect/scale variants. Record measured bounds, visual differences, test scope and remaining limitations.

## Completion evidence

For atlas artwork, record the actual sprite bounds inside each tile and use
cropped UVs plus aspect fitting. Equal tile dimensions do not imply equal object
proportions: a wide rifle in a square tile can render much too small in a correct
multi-cell frame. Check every tile for neighboring fragments, clipped edges and
stretching in both normal and rotated states. Compare the inspection image and
drag thumbnail with the same sprite metadata; independent hand-tuned sizing is
not a reusable correction.

Keep visual and behavioral acceptance distinct. A screen's evidence should identify
the source revision, tested host/platform/renderer, viewport and UI scale, reference
and runtime captures, interaction/invalid-input coverage, and unresolved differences.
Update reusable lessons here when a correction applies to later screens; keep the
specific reproduction and test receipt with the screen or consuming project.

## Native polish checks

Treat passing behavioral tests and rendered-reference review as separate gates. Inspect selected tabs, offscreen selection, light scenery behind reticles, and footer keycaps in native captures. Style focus through each shared control's supported focus property; hiding tree focus does not style tab focus, and suppressing its outline must preserve keyboard navigation. Use the tree's opt-in deferred scroll reveal when programmatic selection should be visible; ordinary same-key synchronization must preserve manual scrolling. Stable node identity alone does not prove a native scroll request survives callback-driven refresh: apply reveal after the projection settles and assert the selected row is actually inside the viewport. Give thin HUD reticles a restrained dark outline when the reference requires contrast over bright scenery.

## Retained spatial controls

Use one aspect-fit transform for background art, overlays and hit testing. Reject input in fit gutters, keep zoom anchored to the pointer, and clamp pan independently on each axis. Treat camera state as view presentation and selected identity as model state; do not invent a second selection cursor when the model already owns a stable key. A legend must match actual marker shapes and colors, and a fixed geographic scale must not survive zoom as misleading text.

Release only the current user/pointer's actual capture before dispatching callbacks that can close, replace or reactivate a screen. Camera commands must reject during an active pan instead of being overwritten by its next move. Test callback-driven teardown and held-gesture teardown, not only ordinary mouse-up. In synthetic Slate tests, keep the pressed-button set alive as long as its FPointerEvent: Unreal retains a pointer to that set. Exercise the routed production path and inspect the real captor.

Schema admission and control semantics are separate checks. Validate normalized coordinates, supported kinds and complete state before publication. A malformed current revision may retain accepted presentation, but must not dispatch stale interaction. Close vector outlines using a copied first point; appending an element from the same TArray triggers aliasing validation. Use an explicit flex spacer for alignment within a row; horizontal-align controls the surrounding slot and does not by itself justify that row's children.
