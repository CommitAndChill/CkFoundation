# CkPixelSprite

Independent indexed XPM sprite data, strict native manifest loading and pure animation timing. This module does not configure the scene-wide CkPixelArt/CkPixelArtRenderer pipeline.

Dependencies: CkCore for FCk_Time; engine Core/CoreUObject/Engine through CkModuleRules. Public UMG and SlateCore support widget headers; private Slate supports presentation, RHI supplies active device texture limits, and Json/Projects support schema recognition and tests. Unity is disabled for self-contained compilation.

The public native value API is CkPixelSprite_Data.h. TryParse_Xpm stages the grid locally and publishes only on success. Failures populate source, line, column, code and message, leaving the caller's grid intact. On 2026-10-11 the maintainer explicitly authorized expected XPM/JSON recognition failures as ordinary structured failures in every build; CK ensures remain reserved for programmer invariants in this parsing boundary. No ensure/build flags are changed.

Supported XPM subset: one optional-static, optional-const char-pointer array declaration with unsized brackets, optional const pointer, comma-separated C string literals and final semicolon. C block/line comments and initial Unicode BOM accepted. Data is printable ASCII after decoding quote/backslash/question/single-quote, octal and hex escapes. Non-printable escapes, concatenated literals, preprocessor statements, multiple arrays and extensions are rejected explicitly. Header has four integers or six with in-canvas hotspot. Whitespace and case in pixel symbols are preserved.

Color selectors c/m/g/g4/s are recognized; c is required and determines the rendered color. Supported c values: None, #RGB/#RRGGBB/#RRRGGGBBB/#RRRRGGGGBBBB, black/white/red/green/blue/yellow/cyan/magenta/gray/grey and grayNN/greyNN percentages. Other X11 color names and color spaces are unsupported errors. Canonical RGB values are straight-alpha sRGB bytes. Derived rendering converts to linear premultiplied colors while interpolating/compositing, then emits straight-alpha sRGB bytes. Specification: https://www.x.org/docs/XPM/xpm.pdf.

Default XPM limits: 8 Mi decoded text characters, dimensions 4096, 1,048,576 pixels, 4096 palette entries, cpp 1–4. uint16 indices accommodate palettes beyond 256 colors. Caller-configured palettes cannot exceed 65536 entries.

TryLoad_Manifest loads strict UTF-8 JSON and every required XPM through the physical filesystem into a temporary manifest, publishing only after all dependencies validate. Each source is bounded to 8 MiB; unique XPM sources total at most 64 MiB. The native loader rejects links/junctions in every traversed component, including the root, even when a link points inside the source folder. Windows local drives and POSIX paths have native inspection implementations; only Windows has been exercised here. This assumes a stable local authoring tree and does not claim race-free confinement against concurrent hostile replacement. Exact path spellings are cached; case aliases may consume separate entries and byte budget on case-insensitive filesystems.

Manifest version 1 has a bounded canvas, 1..1024 named animations, at most 4096 frames and 16 Mi aggregate frame pixels, positive representable durations up to one day, loop/once/ping-pong playback, in-canvas integer anchors, and arbitrary typed JSON events/metadata retained as raw validated JSON. JSON depth is at most 64 and nodes at most 100000 including object keys. Structural fields and authored names are case-sensitive. NUL in animation/anchor names is rejected; NUL in JSON extras survives. Layers are unsupported. Each frame owns authoritative `_DurationMilliseconds` as double; `Get_Duration()` supplies an FCk_Time seconds convenience value. Durations that underflow positive double seconds reject explicitly. Native acceptance status is recorded in PROGRESS.md.

TryEvaluate_AnimationMilliseconds evaluates the authored frame durations and input time using the shortest round-trip decimal representation of each double. Decimal sums, boundary comparisons and modulo keep authored 0.1 + 0.2 millisecond transitions at 0.3 rather than inheriting binary addition drift. TryEvaluate_Animation accepts FCk_Time seconds, shifts its shortest round-trip decimal representation by three decimal places to milliseconds, and avoids an overflowing double seconds-to-milliseconds multiplication. Both publish a frame selection only on success. Selection uses exact decimal boundaries; only the returned local frame time is clamped down to a representable value below the frame duration when needed. The generic TryEvaluate_Frame API below retains its existing seconds-based behavior.

TryPrepare_Animation validates and captures an immutable opaque timeline, owning exact decimal cumulative visit ends, frame ordinals and cycle duration. Runtime players and viewer windows prepare on animation/mode/revision replacement and reuse it through TryEvaluate_PreparedAnimationMilliseconds. Selection binary-searches the first cumulative end strictly above wrapped time. One-shot APIs remain validated convenience wrappers. TryGet_PreparedFrameStartMilliseconds returns an approximate double prefix for explicit inspection; separate manual frame selection represents intervals narrower than a double ULP. Failed preparation and evaluation preserve their output handles/selections.

TryEvaluate_Frame uses absolute signed time, positive finite durations at most 24 hours, and at most 4096 frames. Loop wraps negative time with positive modulo. Once clamps negative time to frame zero and completes at the total duration, retaining the final frame. Ping-pong visits 0..N-1,N-2..1, without duplicate endpoints. Exact boundaries select the next frame. One frame works in every mode; empty/invalid sequences and non-finite time reject without changing output.

UCk_PixelSpriteAsset_UE owns reflected indexed payloads and Unreal-side render settings. A validated immutable native snapshot can outlive replacement; reimport replaces payload atomically. No source parsing occurs during ordinary gameplay. CkPixelSprite_Render.h provides deterministic nearest, linear-premultiplied bilinear and smooth-silhouette rendering. Smooth silhouette interpolates coverage while retaining nearest authored color; it is distinct from bilinear RGB filtering. Scale is 1..8, with optional source-pixel outline, background and temporary palette overrides.

UCk_PixelSpriteResources_UE prepares every unique source texture before publication. Textures are transient BGRA8, sRGB, nearest-filtered and nonstreaming; the CPU renderer already applies the selected derived mode. A cache hit keyed by asset identity, revision, snapshot and settings retains texture identity without uploads. Dimensions obey the active RHI limit, each new generation is bounded to 64 MiB and old/new overlap to 128 MiB. NullRHI uses an explicit 4096 dimension fallback for pure tests; it does not prove GPU output.

UCk_PixelSpritePlayer_UE owns an asset and complete resource generation. One designated owner calls Request_AdvanceMilliseconds; UCk_PixelSpriteWidget_UE passively presents that player and never advances it. UCk_PixelSpritePreview_UE is a ready-to-use viewport widget that owns and advances its private player. Player controls expose named selection, signed direction, speed, loop/once/ping-pong, seek, stepping, pause/resume, normalized time and anchor resolution. Sampling and source-frame decimation affect display only. The accumulated clock is a finite double; exact absolute seeks use the decimal evaluator, while partitioned delta additions retain ordinary binary floating-point rounding. Event JSON is preserved, not automatically dispatched.

TrySample_Time quantizes time downward to a positive presentation interval. This changes presentation frequency without altering playback speed. Runtime player and viewer source-frame decimation affect presentation only; exact manual stepping bypasses presentation decimation. Stepping repositions the clock to an approximate authored start and pins the requested ordinal; Get_LogicalFrame may differ from Get_CurrentFrame at unrepresentable boundaries. Paused or zero-motion advance preserves inspection; a successful seek or actual playback advance clears it.

Native tests: Ck.PixelSprite.* through the host's UnrealToolbox. Shared fixtures are under Tools/CkPixel/Fixtures. Campaign state, executed results and unfinished acceptance requirements are in the host Plans/PixelSprites/PROGRESS.md; source presence is not a passing gate. GPU output, Blueprint/AngelScript operation and cooked runtime require their respective integration checks.
