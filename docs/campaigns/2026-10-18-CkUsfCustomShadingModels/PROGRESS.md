## Decisions and source review

- EngineTypes.h, both material HLSL translators, ShaderGenerationUtil.cpp, ShadingModelsMaterial.ush and ShadingModels.ush supply legacy registration and lighting dispatch. CustomData carries threshold/softness at UNorm8 precision; ClearCoat retains previous wiring.
- `RecompileShaders Changed` flushes source caches and detects transitive includes. Filename-regex global recompilation cannot reliably select every consumer of this shared BxDF include. `Ck_Usf_ReloadShadingModels` enables development mode before invoking Changed; automatic material-look reload remains separate.
- ShaderDevelopmentMode uses the existing repair-and-retry loop. It is not a last-known-good transactional replacement guarantee. Repair on disk before choosing Retry; cancelling a failed global compile can terminate the editor.
- Astra reviewed enum compatibility: tagged enum properties serialize names; old unversioned numeric FromMaterialExpression requires a fork-private migration. The focused test exercises enum-property and unversioned override-struct serialization, not a full material package roundtrip.
- Path tracing's four-bit internal IDs are decoupled from raster model count; opaque CkUsf entries use a DefaultLit fallback. Custom path-traced appearance is unsupported and was not rendered for acceptance.
- One stable early `/CkUsfShadingModel` mapping points to enabled plugin lighting or an engine-owned fallback before shader hashing/types. The mapping is never replaced.
- Source review confirmed HasCustomGBufferData retains the custom payload. Toon-only reserved names do not affect other looks. Mobile/forward checks validate platform metadata before querying it.

## Fixture diagnosis and correction

The first build found a missing UObject/Package.h include, corrected before editor tests. The broad run's initial baseline used the default checkerboard. PostEditChange precompiles with None; a non-null shader map and IsCompilationFinished do not guarantee completeness. The render proxy can submit missing jobs on first draw. Editor PSO component fallback was ruled out from source.

An attempted CacheShaders(Synchronous) readiness fix passed the first capture but failed completeness on subsequent captures. Astra's bounded repeated-failure review identified `UMaterialInterface::EnsureIsComplete()` as the supported production helper, also used by DrawMaterialToRenderTarget. Its implementation explicitly discusses synchronous-cache readiness limitations and submits missing jobs before finishing compilation. The final fixture uses that helper, finishes pending compilation, flushes render commands, and checks game/render-thread shader-map completeness before readback. No speculative DDC diagnosis is treated as established.

The fixture restores exact shader bytes, performs synchronous recovery compilation on failure, and restores CVar value/priority without leaving a Console override. Recovery pixels are asserted on the successful path.

## Acceptance limits and usage

Accepted: desktop deferred, non-Substrate, opaque SurfaceLit Toon, native direct lighting and MID band controls, explicit global reload, same-PID/same-MID HLSL edit and exact-source recovery. Engine and plugin source received bounded independent reviews; the focused gate and final source checks establish the reported result.

Not executed: intentional invalid-HLSL retry dialog, no-plugin engine startup, forward/mobile rendering, path-traced appearance, full package archive compatibility, or manual gym visual approval. The validator rejects unsupported Toon configurations; source checks are not rendering coverage.
